# Woody Puzzle ゲーム仕様書

## 1. プロジェクト概要

Woody Puzzle風のブラウザベースパズルゲーム。プレイヤーは5×5のグリッドボード上に様々な形状のブロックを配置し、行や列を揃えて消去することでスコアを獲得します。ラウンドごとに目標スコアが設定され、それをクリアすることでゲームが進行します。デッキビルディング要素を持ち、各ラウンド後にショップで新しいブロックを選択してデッキに追加できます。

## 2. 技術スタック

- **フロントエンド**: HTML5 / CSS3 / JavaScript (バニラJS)
- **レンダリング**: DOM操作（Canvas APIは不使用）
- **アーキテクチャ**: ES6 Modules不使用、scriptタグによるマルチファイル構成
- **名前空間**: グローバルオブジェクト (`GameBoard`, `BlockManager`, `InputHandler`, `GameUI`, `Shop`, `CONFIG`)
- **ストレージ**: localStorage（ハイスコア保存）
- **デプロイ**: GitHub Pages対応

## 3. ゲームの基本ルール

### 3.1 ボード
- **サイズ**: 5×5グリッド
- **配置ルール**:
  - ブロックはボード内に完全に収まる必要がある
  - 既に配置されたブロックと重複不可
  - 部分的な配置は不可（ブロック全体を配置する必要がある）

### 3.2 手札
- 常に3つのブロックが手札に存在
- ブロックを配置すると、そのブロックは手札から消える
- 3つすべてを配置すると、新たに3つのブロックが配られる

### 3.3 デッキシステム
- **初期デッキ**: ゲーム開始時に8種類のブロックが決定される
  - モノミノ: 1種類（1マス）
  - ドミノ: 2種類（2マス）
  - トロミノ: 5種類（3マス）
- **デッキの再利用**: デッキが尽きると自動的にシャッフルして再利用
- **デッキの拡張**: ラウンドクリア後、ショップで新しいブロックを1つ選んでデッキに追加

### 3.4 ライン消去
- 完成した行または列が自動的に消える
- 複数の行・列が同時に消える場合あり
- 消去時にアニメーション演出（回転、拡大、フェードアウト）

### 3.5 スコアリング
```
獲得スコア = 消去されたブロック数 × 消去されたライン数
```

**例**:
- 1行完成（5ブロック）+ 1列完成（5ブロック）= 重複あり
- 実際の消去ブロック数: 9個（角の1ブロックが重複）
- 消去ライン数: 2
- **獲得スコア**: 9 × 2 = 18点

### 3.6 ラウンド進行
- **目標スコア**: ラウンド数 × 20
  - ラウンド1: 20点
  - ラウンド2: 40点
  - ラウンド3: 60点...
- **配置上限**: 1ラウンドにつき最大12ブロック配置可能
- **クリア条件（いずれかを満たす）**:
  1. 目標スコアに到達
  2. 12ブロック配置完了
- **失敗条件**:
  - 12ブロック配置したが目標スコアに到達していない → ゲームオーバー

### 3.7 ゲームオーバー条件
1. **配置不可**: 手札のすべてのブロックがボード上のどこにも配置できない
2. **目標未達成**: 12ブロック配置後も目標スコアに届かない

## 4. コアメカニクス詳細

### 4.1 ブロック配置システム
- **ドラッグ&ドロップ**:
  - マウス・タッチ両対応
  - ドラッグ中は半透明のプレビューが表示される
  - タッチ操作時は指の60px上にプレビューを表示（指で隠れないように）
- **配置可否のビジュアルフィードバック**:
  - **緑色ハイライト**: 配置可能な位置
  - **赤色ハイライト**: 配置不可能な位置
- **配置判定**: `GameBoard.canPlace(row, col, shape)` で検証

### 4.2 ライン消去システム
- **検出**:
  - 各行・列をスキャンしてすべてのセルが埋まっているかチェック
  - 複数行・列の同時消去に対応
- **アニメーション**:
  - 各ブロックに順次アニメーションを適用（50msの遅延）
  - 回転（360度）+ 拡大（1.2倍）+ フェードアウト
  - アニメーション時間: 300ms
- **スコア演出**:
  1. 消去されるブロック上に「+1」ポップアップ表示
  2. 画面中央に計算式表示（例: `9 × 2 = 18`）
  3. スコアカウンターのアニメーション（easeOutCubic）

### 4.3 デッキ管理システム
- **シャッフルアルゴリズム**: Fisher-Yatesシャッフル
- **ドロー処理**:
  ```javascript
  drawBlocks() {
    // デッキが空なら初期デッキをシャッフルして補充
    if (deck.length === 0) {
      deck = shuffle([...initialDeck]);
    }
    // 3つドロー
    return [deck.shift(), deck.shift(), deck.shift()];
  }
  ```
- **デッキ情報表示**: 「ラウンド X - 残りブロック: Y/Y」（実際の残り枚数は表示されない）

### 4.4 配置不可検出
- **検出タイミング**:
  - ブロック配置後
  - 新しい手札をドロー後
- **処理フロー**:
  1. すべての手札ブロックについて、ボード上のすべての位置で配置可否判定
  2. 1つも配置できない場合、ダイアログ表示
  3. 配置不可能なブロックをすべて「配置済み」扱い（配置カウント増加）
  4. 配置カウントが12に達していれば ラウンド終了処理
  5. そうでなければ次の3つをドロー

## 5. ショップシステム

### 5.1 表示タイミング
- ラウンドクリア後（目標スコア達成 または 12ブロック配置完了）
- ゲームオーバー時（目標スコア未達成の場合は非表示）

### 5.2 ブロック生成ルール
- **スロット1**: 1～2マスのブロック（モノミノ/ドミノ）
- **スロット2**: 3～4マスのブロック（トロミノ/テトロミノ）
- **スロット3**: 4～5マスのブロック（テトロミノ/ペントミノ）
- **ソート**: サイズ順（小→中→大）に並べ替えて表示

### 5.3 選択処理
1. プレイヤーが1つのブロックをクリック
2. 選択されたブロックが `initialDeck` に追加される
3. 次のラウンド開始

## 6. ブロック形状定義

### 6.1 初期デッキブロック（8種類）
```
モノミノ（1種類）:
■

ドミノ（2種類）:
■■    ■
       ■

トロミノ（5種類）:
■■■   ■     ■□    ■■    □■
      ■     ■■    ■□    ■■
      ■
```

### 6.2 全ブロック形状ライブラリ（189種類）
- **1マス**: 1種類
- **2マス**: 2種類
- **3マス**: 4種類
- **4マス**: 19種類（I, O, T, L, Z字型のバリエーション）
- **5マス**: 63種類（F, I, L, N, P, T, U, V, W, X, Y, Z字型のバリエーション）
- **6マス**: 10種類（2×3、3×2の長方形、欠けた形状）
- **7マス**: 8種類
- **8マス**: 6種類
- **9マス**: 1種類（3×3フル）

### 6.3 形状の表現
- 2次元配列で表現（例: `[[1, 0], [1, 1]]`）
- `1`: ブロックが存在するセル
- `0`: 空白セル（`visibility: hidden` で非表示）

### 7.3 各モジュールの詳細

#### config.js
- **役割**: グローバル設定値の定義
- **主要な定数**:
  - `VERSION`: バージョン番号（ビルド時に置換される `__VERSION__`）
  - `BOARD_SIZE`: 5
  - `TOUCH_DRAG_OFFSET_Y`: 60
  - `ANIMATION`: アニメーション設定（duration, delay, scale, rotation）
  - `DECK_BLOCK_SHAPES`: 初期デッキに含まれる21種類のブロック形状

#### board.js (GameBoard)
- **役割**: ボードの状態管理とライン消去
- **内部状態**: `grid` (5×5の2次元配列、0=空、1=埋)
- **主要メソッド**:
  - `init()`: ボード初期化（5×5セルのDOM生成）
  - `clear()`: ボードリセット
  - `canPlace(row, col, shape)`: 配置可否判定
  - `place(row, col, shape)`: ブロック配置（DOM更新）
  - `checkAndClearLines(callback)`: ライン検出→アニメーション→コールバック実行

#### block.js (BlockManager)
- **役割**: ゲーム全体の状態管理、デッキ管理、配置処理
- **内部状態** (`gameState`):
  - `initialDeck`: 初期8種類のブロック（ラウンド間で共有）
  - `deck`: 残りのデッキ
  - `currentBlocks`: 現在の手札（3つ）
  - `round`: 現在のラウンド
  - `score`: 現在のスコア
  - `blocksPlacedCount`: 配置済みブロック数（0～12）
  - `roundEnding`: ラウンド終了処理中フラグ
- **主要メソッド**:
  - `createDeck()`: 初期8種類のデッキ生成
  - `shuffleDeck(deck)`: デッキシャッフル
  - `drawBlocks()`: 3つドロー（デッキ尽きたら再シャッフル）
  - `init()`: ゲーム初期化
  - `render()`: 手札のDOM描画
  - `placeBlock(row, col, block)`: ブロック配置→ライン消去→次のドロー/ラウンド終了判定
  - `checkGameOver()`: 配置不可判定
  - `startNextRound()`: 次ラウンド開始
  - `addBlockToDeck(shape)`: ショップで選択したブロックをデッキに追加

#### input.js (InputHandler)
- **役割**: ドラッグ&ドロップ処理
- **内部状態**:
  - `dragState`: ドラッグ中の情報（block, offsetX, offsetY, isDragging）
  - `dragPreview`: ドラッグプレビュー要素
- **主要メソッド**:
  - `startDrag(event, block)`: ドラッグ開始
  - `onDragMove(event)`: ドラッグ中（プレビュー移動、ハイライト更新）
  - `onDragEnd(event)`: ドロップ処理（配置実行 or キャンセル）
  - `updateDragPreview(x, y)`: プレビュー位置更新
  - `highlightCells(row, col)`: セルのハイライト（緑/赤）
  - `clearHighlight()`: ハイライト解除

#### ui.js (GameUI)
- **役割**: UI更新、スコア演出、ダイアログ表示
- **主要メソッド**:
  - `updateScore(points)`: スコア加算
  - `resetScore()`: スコアリセット
  - `showScoreCalculation(blocksCleared, linesCleared, totalScore, callback)`: スコア計算式表示
  - `animateScoreIncrement(start, end, duration)`: スコアカウンターアニメーション
  - `showGameOver(reason, round)`: ゲームオーバー画面
  - `updatePlacementInfo(blocksPlaced, round)`: 配置進捗表示
  - `updateTargetScore(round)`: 目標スコア表示
  - `showCannotPlaceDialog(callback)`: 配置不可ダイアログ（3秒後にコールバック）
  - `showRoundEnd(round)`: ラウンド終了判定→ショップ表示 or ゲームオーバー
  - `saveHighScore(round)`: ハイスコア保存（localStorage）
  - `loadHighScore()`: ハイスコア読み込み

#### shop.js (Shop)
- **役割**: ショップのブロック生成と選択処理
- **主要メソッド**:
  - `generateSlot1Block()`: 1～2マスブロック生成
  - `generateSlot2Block()`: 3～4マスブロック生成
  - `generateSlot3Block()`: 4～5マスブロック生成
  - `show()`: ショップ表示（3つのブロック生成→ソート→DOM描画）
  - `hide()`: ショップ非表示
  - `selectBlock(shape)`: ブロック選択→デッキに追加→次ラウンド開始

#### main.js
- **役割**: ゲームエントリーポイント
- **主要関数**:
  - `initGame()`: ゲーム初期化（Board, UI, BlockManager初期化、イベントリスナー登録）
  - `restartGame()`: ゲーム再スタート
- **イベントリスナー**:
  - `#restart-button`: リスタートボタン
  - `#settings-icon`: 設定アイコン（データリセット確認）

## 9. ゲーム進行フロー

### 9.1 ゲーム開始
```
1. initGame() 実行
2. GameBoard.init() → 5×5セル生成
3. GameUI.init() → スコア表示、ハイスコア読み込み
4. BlockManager.init() → 初期デッキ作成、3つドロー
5. checkGameOver() → 配置可否チェック
```

### 9.2 ブロック配置
```
1. プレイヤーがブロックをドラッグ開始
2. InputHandler.startDrag() → dragState設定、プレビュー作成
3. ドラッグ中: updateDragPreview() → プレビュー移動、ハイライト更新
4. ドロップ: onDragEnd()
   → GameBoard.canPlace() で配置可否判定
   → OK: BlockManager.placeBlock() 実行
   → NG: キャンセル
5. placeBlock()
   → GameBoard.place() → ボード状態更新、DOM更新
   → blocksPlacedCount++
   → checkAndClearLines() 実行
6. checkAndClearLines()
   → ライン検出
   → アニメーション実行
   → スコア計算・演出
   → コールバック実行
7. コールバック内
   → 目標スコア達成? → ラウンド終了
   → 12ブロック配置? → ラウンド終了
   → 手札3つすべて配置? → 次の3つドロー
   → checkGameOver() 実行
```

### 9.3 配置不可検出
```
1. checkGameOver() 実行
2. すべての手札について全位置で配置可否判定
3. 1つも配置できない
   → showCannotPlaceDialog() 表示（3秒）
   → コールバック内:
     - 配置不可能ブロックを「配置済み」扱い
     - blocksPlacedCount 増加
     - 12ブロック到達? → ラウンド終了
     - そうでない → 次の3つドロー → 再度 checkGameOver()
```

### 9.4 ラウンド終了
```
1. showRoundEnd() 実行
2. 目標スコア達成判定
   → 達成: Shop.show() → ショップ表示
   → 未達成: showGameOver() → ゲームオーバー
```

### 9.5 ショップ
```
1. Shop.show() → 3つのブロック生成（サイズ別）
2. プレイヤーが1つ選択
3. selectBlock(shape)
   → BlockManager.addBlockToDeck(shape) → initialDeck に追加
   → BlockManager.startNextRound()
4. startNextRound()
   → round++
   → スコアリセット
   → ボードクリア
   → デッキ再シャッフル
   → blocksPlacedCount = 0
   → roundEnding = false
   → 3つドロー
   → UI更新
```

### 9.6 ゲームオーバー
```
1. showGameOver(reason, round)
   → 理由表示（"目標スコアに届きませんでした" or "配置できません"）
   → 最終ラウンド表示
   → ハイスコア保存・表示
2. プレイヤーが「もう一度遊ぶ」クリック
   → restartGame() → initGame() 再実行
```

## 11. 特殊な実装の詳細

### 11.1 コールバック駆動アーキテクチャ
- アニメーション完了後にゲームロジックを実行
- 例: `checkAndClearLines(callback)` → ライン消去アニメーション完了後にコールバック実行
- レースコンディション防止のため重要

### 11.2 ラウンド終了フラグ
- `roundEnding` フラグでラウンド終了処理中の配置を防止
- ショップ表示中に配置されないように制御

### 11.3 デッキの無限シャッフル
- `initialDeck` を保持し続け、`deck` が空になるたびに `initialDeck` をコピー&シャッフル
- 同じブロックセットが何度も出現する仕様

### 11.4 配置不可時の強制進行
- 配置できないブロックを「配置済み」としてカウント
- 12ブロック上限に達するまで自動的にドローを続ける

### 11.5 スコアアニメーション
- easeOutCubic イージング関数を使用
- 滑らかなカウントアップアニメーション
- 計算式表示 → 数値カウントアップ → コールバック の順に実行

### 11.6 ブロック消去のスタッガードアニメーション
- 各ブロックに50msの遅延を適用
- 順次消えていく演出で視覚的にわかりやすい

## 13. 既知の仕様

### 13.1 仕様として確定している動作
- デッキは無限に再利用される（同じブロックが繰り返し出現）
- 配置不可能な場合、強制的にブロックを「配置済み」扱いにして進行
- 12ブロック配置制限により、配置不可状態でも必ずラウンド終了に到達
- 目標スコアは達成 OR 12ブロック配置のどちらかでラウンドクリア
- ショップでは必ず小→中→大の順にソートされて表示

### 13.2 意図的な設計選択
- ES6 Modules不使用（GitHub Pagesでのシンプルなホスティングのため）
- Canvas不使用（DOM操作のみで実装、デバッグ容易性のため）
- グローバルオブジェクト使用（モジュール間の依存関係を明確にするため）
